# Fintech Hackathon

Landing page, submission portal, judging portal and organiser console for the Fintech Hackathon
(London, 13 October 2026, by Singapore Global Network × Generate at LSE). Live at **[shiptonight.com](https://shiptonight.com)**.

One Node process, no dependencies, SQLite on disk (`node:sqlite`, Node 22.13+).

| Page | Who | What |
| --- | --- | --- |
| `/` | Everyone | Event page: tracks, criteria, judges, how judging works, sponsors |
| `/submit` | Teams | Submit a project; returns a private edit link |
| `/judge` | Judges | Swipe-style scoring, top 3 picks, shortlist and finals rounds |
| `/admin` | Organisers | Phase control, judge links and progress, reassignment, finalists, winners, CSV |
| `/results` | Projector | Click-to-reveal winners (public once the phase is "Results") |

## Submitting with an AI agent

Teams can have their coding agent (Claude Code, Cursor, Codex, Foldo) submit for them. Paste this one-liner:

```
Read https://shiptonight.com/submit.md and follow it to submit this project to the Fintech Hackathon.
```

[`/submit.md`](public/submit.md) tells the agent how to draft the entry from the repo and ask the human for anything it
can't verify. That covers team members, LinkedIn links, email and the demo video, which it must never invent. It then
validates with `POST /api/submissions?dryRun=1`, gets an explicit yes, submits, and hands back the private `editUrl`.
Resubmitting the same title from the same email returns `409`, so retries can't create duplicates. `/llms.txt` points
agents to the instructions, and both files fill in the host they're served from.

## Run locally

```sh
npm start                 # http://localhost:3000, admin key "admin-local"
```

Judge links are printed on start and shown in `/admin`. Four named judges plus two optional slots: add a judge in
`/admin` and unscored entries are re-split across everyone; mark a judge absent and theirs move to the others.

## Testing

All test scripts write junk data, so point them at a throwaway `DB_PATH`.

```sh
npm run load-test -- http://localhost:3000 80                 # N simultaneous submissions + page loads
node scripts/adversarial.mjs http://localhost:3000 admin-local # 58 checks: malformed requests, auth, phases, races, CSV, rate limits
node scripts/stress.mjs <url> <admin-key> 60 120 300           # burst + 60s of browsing participants, judges and admin
```

Last live run (Railway, 1 replica): 300 simultaneous submissions plus 120 browsing participants, judges polling at
10× and the admin console, with 0 errors and p99 under 2 s for every request type.

## Field guides

`guides/` holds the one-page A4 judge and mentor guides (`judge-guide.pdf`, `mentor-guide.pdf`), built from HTML with
artwork generated by GPT Image 2.5. `guides/art/mockups` keeps the page mockups the design was chosen from.

## Deploy to Railway

1. Create a service from this folder (`railway up`). It builds with the `Dockerfile`.
2. Add a **volume mounted at `/data`**. Without it, submissions are lost on redeploy.
3. Set `ADMIN_KEY` to a long random string. Optional: `JUDGE_CODE_NUAN`, `JUDGE_CODE_TILL`, `JUDGE_CODE_ANNA`, `JUDGE_CODE_LUKA` to fix judge codes.
4. Generate a domain. Keep **one replica** (SQLite lives on the volume).

## How judging works

1. **Submissions open.** Each new submission is assigned to the judge with the fewest projects in that track, so
   every judge gets a balanced share of every track. Judges can start scoring as projects arrive.
2. **Round 1 · Review.** Submissions close. Judges watch each demo (1:30 limit, with a clock on the card), score four
   criteria from 1 to 5 (weights 30/25/25/20, giving a score out of 100) and swipe right (contender) or left (pass).
   They then confirm one top pick per track. A judge who never opens the picks tab gets their best-scored project in each
   track picked automatically.
3. **Round 2 · Shortlist.** All judges score every pick (up to 12). The top 6 by average become finalists, with at
   least one per track. Organisers can override this in `/admin`.
4. **Finals.** The 6 present live and judges score them. Overall winner = best average; each track winner = best in that
   track, excluding the overall winner where another finalist exists. Organisers can override.
5. **Results.** `/results` goes public. Click each card to reveal.

Keyboard shortcuts for judges: `1`–`5` scores the highlighted criterion, `→` contender, `←` pass, `↓` later, `Backspace` undo.
